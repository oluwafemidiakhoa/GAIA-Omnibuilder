# GAIA Omnibuilder OS v0.6 — paired contract benchmark

The new module freezes a suite of operator contracts and independently scores paired baseline/candidate proposals using v0.5's oracle. No API calls, code execution, or execution authorization occur in the benchmark. Prior v0.5 code is preserved.

## Windows PowerShell

From the extracted gaia-os-v06 folder:

```powershell
python -m unittest discover -s tests -v
python benchmark.py freeze benchmark-cases.json --out my-frozen.json
python benchmark.py score my-frozen.json benchmark-fixture.json --expected-hash b6bf132396f0c33c79bf9a0e0ccbbccbb814ff4a6e7467f14b61699815928ec6 --out my-benchmark.json
```

Use new output filenames on repetition. Expected 84 tests. The expected hash must be obtained from a separately trusted record before scoring; the bundled example is not an external trust anchor. Compare hashes across platforms.

## Protocol and limitations

Ten public development cases (eight sums, two echoes). Freeze exact inputs, expected outputs, allowed operations, task IDs and dependencies before collecting proposals. Candidate and baseline responses use the same case IDs. Missing pairs are explicitly incomplete; invalid submitted proposals count as failures. Report complete-pair pass counts, paired difference, discordant wins/losses, ties and two-sided exact binomial sign test for complete suites. Statistical inference requires independently sampled exchangeable paired cases; these hand-built fixtures do not meet that requirement. No confidence interval or generalization claim is made. All response imports are unauthenticated. The demo deliberately injects errors into both arms; 7/10 versus 9/10 is a scorer self-test, not a measured benefit. No held-out data, live inference, matched budget verification, cost/latency collection, provider authentication or promotion criterion is implemented. No arbitrary code or scientific conclusions are scored.

## Real evaluation next

Freeze a separate held-out suite before inference, keep answers hidden from model prompts, use same model/version and matched request/token budgets in each arm, counterbalance order, independently capture raw provider responses and usage, retain every failure, and predeclare statistical and practical thresholds. The current scorer accepts imports with kind `unverified_import` using the same structure as benchmark-fixture.json; it never authenticates them or authorizes promotion. Do not send private data or spend money without explicit permission. The contract scorer measures exact plan agreement, not natural-language satisfaction or observed execution.
