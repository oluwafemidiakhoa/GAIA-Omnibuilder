# v0.5 — Independent contract verification

Run `python -m unittest discover -s tests -v`. The original 60 tests are preserved; 12 verifier tests are added.

Use `python planner.py --mission "Add 2, 3, 5" --capability architecture --policy demo-policy.json --out my-proposal.json` and `python verifier.py --proposal my-proposal.json --contract oracle-contract.json --policy demo-policy.json --out my-report.json`. The output must be a new file. The mock is a fixture, not an AI model.

The operator contract is independently supplied and defines exact tasks, inputs, dependencies and expected outputs. The verifier recomputes sum, echo and collect using a separate implementation, checks exact task membership, policy binding and budget, and records hashes. Exit 0 means contract checks passed; 1 means checks failed; 2 means invalid input or I/O failure. `wrong-proposal.json` deliberately changes the expected sum to 11; `wrong-report.json` documents rejection.

No execution or authorization is granted. A PASS is restricted to the supplied contract; it does not establish natural-language mission satisfaction, actual execution, live provider behavior, provenance authentication or correctness for arbitrary software. The verifier is separate from the runner and is not a mandatory gate on legacy interfaces. Contract authorship and independence are trusted operator responsibilities. No live network calls were made. Windows testing is pending. Initial two test failures came from unsorted policy fixture; sorted fixture matches canonical policy format. No verifier check was weakened.

Prior release manifests and test outputs are historical evidence; the v05 manifest describes the new release.
